# Олон компани (2+) — эзний шаардлага (2026-11-17)

> Эзний үг: «Би цаашдаа 2 компанид энэ ERP-г ашиглах болохоор заавал тохиргоо хэсэгт бичүүлээд API сольж болдог хийлгэж байгаа юм.
> Тус бүр өөрсдийн дата, өөрсдийн торгууль, өөрсдийн зүйлтэй. Жишээлбэл: нэг нь гүйцэтгэлээр цалингаа боддог,
> нөгөөх нь гүйцэтгэлгүй цалин боддог. Үүнийг маш сайн тэмдэглэж ав.»

## 1. Шаардлага
- ERP-г **2 (цаашид илүү) тусдаа компани** ашиглана. Код нэг, гэхдээ компани бүр:
  - **өөрийн өгөгдөл** — захиалга, бараа, агуулах, жолооч, ажилтан, үйлчлүүлэгч, тайлан;
  - **өөрийн дүрэм** — торгуулийн нэрс, дүн; цалингийн арга (гүйцэтгэлээр / гүйцэтгэлгүй — тогтмол);
  - **өөрийн холболт** — SMS үйлчилгээ (API, түлхүүр), банкны данс, Meta Pixel, Gmail, пэйжүүд;
  - **өөрийн тохиргоо** — хүргэлтийн төлбөр, төлбөр хүлээх хоног, хуваарилалтын цаг г.м.
- Нэг компанийн өгөгдөл нөгөөд **хэзээ ч харагдахгүй, холилдохгүй**.

## 2. Бүх агентад заавал мөрдөх дүрэм (одооноос)
1. **Компани бүрт ялгаатай байж болох зүйлийг кодонд бичихгүй (hardcode хийхгүй).** Бүгд Тохиргоо (database) -д,
   Супер админ гараар засдаг байна. Үүнд: үнэ, хувь, дүн, цалингийн арга, торгууль, данс, API хаяг/түлхүүр, мессежийн текст, цаг, хоног.
2. Кодонд **компанийн нэр, дансны дугаар, түлхүүр, утас** бичихгүй. Анхдагч утга нь ерөнхий (жишээ) байна.
3. Шинэ модуль / өөрчлөлт бүрийн өмнө асууна: «Хоёр дахь компани үүнийг өөрөөр хэрэглэвэл тохиргоогоор солигдох уу?»
4. Гадны үйлчилгээ (SMS, банк, Meta…) — **солигдох боломжтой** хийнэ (#166 SMS шиг: хаяг + загвар Тохиргоонд).

## 3. Одоо тохиргоогоор солигдох зүйлс (2026-11-17)
| Зүйл | Хаана | Тайлбар |
|---|---|---|
| Жолоочийн цалин: гүйцэтгэлээр / 1 хүргэлт тогтмол | Тооцоо → «Цалингийн дүрэм» (`SalaryRule`, өгсөн өдрөөс) | Компани бүр өөрийн дүрэмтэй |
| Жолооч бүрийн горим (энгийн / тусгай / орон нутаг) | Тооцоо → «Гүйцэтгэл солих» (`DriverPayMode`) | |
| Ажилтны цалин: тогтмол (FIXED) / захиалгаар (ORDER_BASED) | Цалин → ажилтны тохиргоо (`StaffSalaryConfig`) | Хүн бүрээр |
| Торгуулийн нэрс, дүн, автомат торгууль | Алдаа удирдлага, Тохиргоо → Торгуулийн дүн | |
| Хүргэлтийн төлбөр, хүлээх хоног, хуваарилалтын цаг | Тохиргоо → Хүргэлт ба төлбөр | |
| SMS (текст, данс, API хаяг, түлхүүр) | Тохиргоо → SMS (#166) | |
| Meta Pixel, Gmail, пэйжүүд, ажлын байрны IP | Тохиргоо | |

## 4. Мэдэгдэж буй хязгаар (2 дахь компанид хэрэгтэй бол засна)
- **Банкны импорт зөвхөн Хаан банкны** мессеж / CSV хэлбэрийг уншдаг. Нөгөө компани өөр банк хэрэглэвэл тэр банкны задлагч нэмэх шаардлагатай.
- Брэнд (лого «zahialga•», гарчиг) кодонд байна — компани бүрийн нэр/логог Тохиргоонд гаргах эсэхийг шийднэ.
- SMS-ийн Латин хөрвүүлэлт, Монгол утасны 8 оронтой формат — Монголд хамаарна.

## 5. Архитектурын санал (эзний шийдвэр хүлээгдэж байна)
**Санал: компани бүрт тусдаа суулгац** — нэг код, гэхдээ компани бүрт тусдаа сервер (эсвэл тусдаа Docker stack) + **тусдаа database** + тусдаа нөөц хуулбар.
- Давуу тал: өгөгдөл холилдох эрсдэл **0**; нэгийнх нь ачаалал, алдаа нөгөөд нөлөөлөхгүй; нөөц, сэргээлт тусдаа; одоогийн код бараг өөрчлөгдөхгүй.
- `./update.sh` компани бүрийн сервер дээр тус тусдаа ажиллана (нэг кодоос).
- Альтернатив (нэг database-д олон компани — `companyId` багана бүх хүснэгтэд) нь том өөрчлөлт, өгөгдөл холилдох эрсдэлтэй тул **санал болгохгүй**.
