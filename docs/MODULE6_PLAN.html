Нягтлан — жолоочийн тооцоо, цалин, өр, банкны импорт

2026.11.11 · Хуучин ERP-ийн нягтлангийн бүх хуудсыг (нягтлан, жолоочийн «Орлого», өрийн бүртгэл, урьдчилгаа, OKEY, банкны импорт) мөр мөрөөр уншсан дүн, таны хариулт. Хуучин бүх боломж орно. Таныг «Модуль 6-ын төлөвлөгөөг зөвшөөрч байна» гэж бичихээс өмнө код бичихгүй.

1. Хуучин ERP-ийн хуучин алдаа (V2-т давтахгүй)

  • Огноо зөрдөг: нягтлан «үүссэн өдрөөр», жолооч «хуваарилсан өдрөөр», тооцоог «өмнөх өдөр» гэж хадгалдаг — тоо байнга зөрдөг. → V2: бүгд хүргэсэн өдрөөр (B1), цуцалсан/маргааш — тэр үйлдлийн өдрөөр.
  • Цалингийн томъёо 6 газар өөр өөрөөр (зарим нь UTC цагаар, хянах самбар хуучин дүрмээр). → V2: нэг л функц, жолооч ба нягтлан ижил тоо харна.
  • Тушаах дүнг жолоочийн утас илгээдэг, сервер шалгадаггүй; «Тооцоо хийсэн» тэмдэг нэвтрэлтгүй. → V2: сервер өөрөө тооцно, бүх товч эрхтэй.
  • Өнгөрсөн өдрийн тооцоо чимээгүй өөрчлөгддөг (өр хаах, төлөв солих, гүйцэтгэлийн тохиргоо солих). → V2: баталгаажсан өдөр түгжигдэнэ; тохиргооны өөрчлөлт өгсөн өдрөөсөө л.
  • Банкны импорт: мөнгө ГАРСАН гүйлгээг ч төлбөр гэж тоолдог, хэн ч бүгдийг устгах боломжтой, хуучин захиалгыг цуцалж шинэ дугаартай үүсгэдэг. → V2: зөвхөн орлого, эрхтэй, дугаар солигдохгүй.
  • Хүснэгтийн «Тооцоо хийсэн / нийлсэн» гарчиг солигдсон, итгэлтэй жолоочийг сервер хориглодог гэх мэт жижиг алдаа.

3. Хуудсууд — хуучин бүх боломж

  1. Нягтлан (/accounting) «Нягтлан бодох бүртгэл»: өдөр сонгох (‹ ›, календарь, сүүлийн 3 өдөр + маргааш товч); шүүлт (жолооч, төлөв, орон нутаг/энгийн); товчнууд OKEY, Гүйцэтгэл солих (Супер админ), Төлбөр тооцооны бүртгэл, Падаан.
    • Картууд: Нийт захиалга, Хүргэсэн, Цуцласан, Орон нутаг, Жолооч цалин, Хүлээн авах дүн (= хүргэсэн − орон нутаг − цалин), «Тооцооны задаргаа», «Тооцоо нийлсэн» (Бэлэн / Дансаар / Өр, нийт урьдчилгаа, нийт нэмэлт бараа), «нийлсэн / хүсэлт явуулсан / огт явуулаагүй» жолоочийн тоо.
    • «Жолооч бүрийн хураангуй»: Жолооч, Нийт, Хүргэсэн, Хүргэлтэд, Цуцласан, Гүйцэтгэл (✏️ Засах, «Гараар засагдсан a% → b%»), Нэг захиалга (≥35 / <35), Дүн, Цалин, Хүлээн авах, «Тооцоо хийсэн» тэмдэг, «Тооцоо нийлсэн» (Бэлэн/Данс/Өр, «Тооцоо нийлэх» товч, урьдчилгаа ба нэмэлт барааны тооцоо «Зөвшөөрөх»), «НИЙТ ДҮНГЭЭР».
    • «Өнөөдөр өр тавьсан», «Өнөөдөр өр төлсөн».
    • Жолооч дээр дарахад: бүх үзүүлэлт, «Тооцооны задаргаа», «Гүйцэтгэлийн тооцоо» (дүрэм, одоогийн мөр), «Төлбөрийн мэдээлэл», падаантай тулгалт («✅ ПАДААН ТААРСАН» / «⚠️ Зөрүү»), нэмэлт бараа («⚠️ Тооцоонд орохгүй»), хэсэгчилсэн хүргэлт, өр, торгууль (мэдээлэл), захиалгын жагсаалт (тэмдгүүд, түүх).
    • «Төлөв солих» (нягтлан аль ч өдрийн захиалгад): Хүргэлтэд → Хүргэсэн/Цуцласан, Хүргэсэн → Цуцласан, Цуцласан → Хүргэсэн — бараа журналаар зөв хөдөлнө (жолоочийн нэрийн өмнөөс, B2).
    • OKEY цонх (өнөөдөр: Зөвшөөрөх / Цуцлах, Итгэмжлэх), «Гүйцэтгэл солих» цонх (Тусгай / Орон нутаг, хөлс), «Төлбөр тооцооны бүртгэл» (жолооч бүрийн өр, «Өр нэмэх», «Өр хасах»).
  2. Жолоочийн апп — «Орлого» таб (хуучин шиг): өдөр сонгох; Нийт / Хүргэсэн / Цуцласан; «Гүйцэтгэлийн тооцоо» (дүрэм, тусгай/орон нутаг тэмдэг); Бэлэн / Данс / Нийт; орон нутаг, цуцлагдсан, цалин, нэмэлт бараа; «Авах дүн»; дуусаагүй захиалгын анхааруулга.
    • «Тооцоо нийлэх»: Бэлэн + Данс + Өр = Авах дүн (Данс урьдчилж бөглөгдөнө) → нягтлан баталгаажуулна; хүлээгдэж байхад «Тооцоо буцаах». Баталгаажсаны дараа тэр өдөр түгжигдэнэ; «Өр» нь жолоочийн өрийн бүртгэлд.
    • «Нэмэлт барааны тооцоо», «Урьдчилгаа шилжүүлэх» (дүн, тайлбар) → нягтлан «Зөвшөөрөх» (хуучин шиг, Авах дүнд орохгүй).
  3. Жолоочийн «Төлбөр тооцоо» (зөвхөн харах): компанид өгөх өр — идэвхтэй ба түүх.
  4. Өрийн бүртгэл: төрөл — Агуулахад бараа буцаагаагүй, Бараа хүргээгүй, Нягтлантай нийлээгүй, Тооцоо нийлэхэд үүссэн өр, Бусад. Дутуу бараа (таны шийдвэр): жолоочийн гарт буцаагаагүй бараа өдрийн эцэст автоматаар өр болно (системийн үнээр); агуулахад буцааж өгөхөд өр автоматаар хаагдана — жолоочийг хохироохгүй, үлдэгдэл зөрөхгүй.
  5. Банкны импорт (/bank-import), хуучин шиг + нягтлан: Хаан банкны CSV импорт, Gmail sync (имэйлээр ирсэн мессеж — таны Gmail-ийн зөвшөөрөл тохируулах шаардлагатай), огноо, статистик (Нийт, Таарсан, Таараагүй, Хэсэгчлэн, Илүү, Давхардсан, Буцаасан), табууд, хайлт, «Гараар тааруулах», «Буцаасан» тэмдэг, «Дүн өөрчлөгдсөн», CSV экспорт. Утас + дүнгээр «Төлбөр хүлээж буй» захиалгыг олж «Мөнгө орсон» болгоно (Meta илгээгдэнэ); захиалгын дугаар солигдохгүй; зөвхөн орлого; давхардал илрүүлнэ. Эрх: ахлах оператор, админ импортлож тааруулна, оператор харна, нягтлан харж тааруулна.

4. Таны шийдвэр (#82)

  1. Үйлчлүүлэгч төлөөгүй дүнг жолооч тушаана (хуучин шиг).
  2. Тооцоо нийлэх — хуучин шиг (Бэлэн/Данс/Өр, нягтлан баталгаажуулна).
  3. Цалин — яг хуучин шиг, бүх логиктой; хөлс ба гүйцэтгэлийн босгыг тохиргооноос өөрчилдөг болгоно.
  4. «Маргааш» ба асуудлын цуцлалт гүйцэтгэлд — яг хуучин шиг.
  5. Банкны импорт — хуучин шиг + нягтлан.
  6. Дутуу бараа — автоматаар өр, буцаахад автоматаар хаагдана.

5. Ажлын дараалал ба тест

  1. Өгөгдлийн сан: өдрийн тооцоо (жолооч + өдөр давтагдашгүй), өрийн бүртгэл, урьдчилгаа, нэмэлт барааны тооцоо, цалингийн тохиргоо (өдрөөр), жолоочийн горим (өдрөөр), гараар засах гүйцэтгэл, банкны гүйлгээ.
  2. Нэг тооцооны функц → нягтлан, жолоочийн «Орлого», тайлан бүгд үүнийг ашиглана.
  3. Хуудсууд: Нягтлан, жолоочийн «Орлого», «Төлбөр тооцоо», Банкны импорт.
  4. Тест: жолоочийн ба нягтлангийн тоо яг ижил; хэсэгчилсэн хүргэлт (#73); өрийн дэвтэр нягтлантай холбоогүй (#79); хүргэсэн өдрөөр (B1); баталгаажсан өдөр түгжигдэх; дутуу барааны өр автоматаар үүсч хаагдах; банкны давхардал, хэсэгчилсэн, илүү; үлдэгдэл 0 зөрүү (B2); урт текст (B3); 150 хэрэглэгчийн ачаалал; Docker.
  5. Тайлан → таны баталгаа.
Танаас: зөвшөөрвөл «Модуль 6-ын төлөвлөгөөг зөвшөөрч байна» гэж бичнэ үү. Өөрчлөх, нэмэх зүйл байвал хэлээрэй. Gmail sync-ийг ажиллуулахад тухайн Gmail-д нэвтрэх зөвшөөрөл хэрэгтэй — хэрэгжүүлэх үед тусад нь заавар өгнө.
Хуучин ERP-д хүрээгүй (зөвхөн кодыг уншсан). Бодит өгөгдөл ашиглаагүй.
