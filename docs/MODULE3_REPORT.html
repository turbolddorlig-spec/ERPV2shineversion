1. Юу хийсэн

  • Нэг дэлгэцээр захиалга авах: утас (хуулж буулгахад зай, +976 автоматаар цэвэрлэнэ), нэмэлт утас, аймаг/хот → дүүрэг → хороо (эсвэл «Хороо тодорхойгүй»), байр/тоот. Бүтэн хаяг доор нь автоматаар бүрдэнэ: «Улаанбаатар, Баянзүрх дүүрэг, 13-р хороо, 45-р байр…».
  • Нэг «Захиалга үүсгэх» товч — төлөв автомат: орон нутаг → «Төлбөр хүлээж буй»; УБ → «Шинэ»; хүргэх өдөр маргаашаас хойш → «Он сар өдөртэй». Хүргэх өдөр: Маргааш (анхдагч) / 🔴 Өнөөдөр / Өөр өдөр.
  • Үйлчлүүлэгчийн карт: утсыг бичмэгц өмнөх захиалгууд, хүргэсэн/цуцалсан тоо, сүүлийн хаяг («Энэ хаягаар» нэг товч), хар жагсаалт, дуудлагын тэмдэглэл.
  • Давхардал: аль нэг утас (нэмэлт утас ч) идэвхтэй захиалгатай бол шинээр үүсгэхгүй — «№… захиалгад бараа нэмэх» товч гарна (#51).
  • Бараа: код/нэр/өнгөөр хайх, зураг томруулах, боломжтой тоо, тайлбар; пэйжийн 7 хоногийн түгээмэл бараа нэг даралтаар (туршилт — хэцүү бол хасна). Үнэ зөвхөн бууруулна, шалтгаантай; Супер админ «Хөнгөлөлт шалгах»-аас батална.
  • Хүргэлтийн төлбөр: «Үнэд хүргэлт багтаагүй» бараатай бол УБ 5,000₮ / орон нутаг 10,000₮ (Тохиргоо) нэг удаа нэмэгдэнэ; оператор шалтгаантай өөрчилнө. Бараа засах дэлгэцэд «Үнэд хүргэлт багтсан» чагт нэмэгдсэн.
  • Нөөц: захиалга үүсэхэд бараа нөөцлөгдөнө, засахад зөрүүгээр нэмэгдэж/суллагдана, цуцлахад бүрэн суллагдана. Агуулахад «N төлб.» — орон нутгийн төлбөр хүлээж буй нөөц харагдана.
  • Орон нутаг: 7 хоног (тохируулна) мөнгө хүлээнэ, хугацаа дуусвал автоматаар цуцлагдаж нөөц суллагдана. Ахлах оператор/админ «Мөнгө орсон», «+3 хоног», буцаах.
  • Цуцлах: 6 шалтгаан + тайлбар заавал; бүх өөрчлөлт «Түүх»-д (хэн, хэзээ, юуг юу болгосон).
  • Хар жагсаалт: анхааруулна, оператор шалтгаан бичиж үргэлжлүүлнэ; ахлах оператор удирдана.
  • Дуудлагын бүртгэл (хуучин логик): олон дугаар зэрэг, 5 оролдлого/30 мин, шилжүүлэх хүсэлт, ахлах шууд шилжүүлэх, «Захиалга болгох». Хаахад шалтгаан заавал — систем санал болгоно (#54).
  • Пэйж: Тохиргоонд пэйж нэмэх/нуух; ахлах оператор операторт пэйж хуваарилна; оператор сүүлд сонгосон пэйж хадгалагдана.
  • Цагийн мэдээ (11, 13, 15, 18, 21 цаг) бүх операторт; Пэйжийн тайлан (зөвхөн тоо: пэйж/оператор/өдөр/бараагаар, Excel) ба Дуудлагын шинжилгээ (захиалга болсон уу, болоогүй бол яагаад; дугааруудын жагсаалт) — зөвхөн Супер админ, маркетинг.
  • Meta CAPI: захиалга баталгаажихад «Purchase» мэдээ нэг удаа (утас hash-тай), алдаа гарвал дахин оролдоно. Pixel/токен Тохиргоонд; токен хадгалсны дараа хэзээ ч харагдахгүй. Pixel тохируулаагүй үед «алгассан».

2. Хуучин ERP-ийн асуудлууд яагаад гарахгүй вэ

  • Давхар захиалга: давхар дарах, сүлжээ тасарч дахин илгээх → нэг түлхүүрээр нэг л захиалга. Хоёр оператор нэг утсаар зэрэг → утсаар түгжиж, нэг нь л үүснэ. Тест: 5 зэрэг ижил хүсэлт → 1; ачааллын тестэд 150 хэрэглэгч → давхар 0.
  • Сүүлийн 1 бараа хоёр захиалгад: бараагаар түгжиж, боломжтойг дахин шалгана → нэг нь «хүрэлцэхгүй». Үлдэгдэл хэзээ ч сөрөг болохгүй.
  • Засвар ба цуцлалт зэрэг: хувилбарын дугаараар — хуучин дэлгэцээс хадгалах гэвэл «Өөр хүн өөрчилсөн, дахин ачаална уу».
  • Падаанд орсон захиалгын бараа засагдахгүй (Модуль 4-т падаан нэмэгдэхэд шууд ажиллана).
  • Дүн: серверт тооцно (бараа − хөнгөлөлт + хүргэлт), database-ийн хязгаарлалт давхар шалгана; үнэ нэмэх боломжгүй.

10–11. Бусад модульд нөлөө ба өгөгдлийн аюулгүй байдал

  • Модуль 1: бараанд нэг чагт нэмэгдсэн (анхдагч «багтсан» — одоогийн бараанд нөлөөгүй). Бараа хайлт «боломжтой тоо»-г нөөцийг хасаж харуулна.
  • Модуль 2: агуулахын «боломжтой» нь захиалгын нөөцийг хасна; «N төлб.» шинэ. Журнал ба тулгалт хэвээр — захиалга үлдэгдлийг шууд хасахгүй, зөвхөн нөөцөлнө (бараа гарах нь Модуль 4 падаан).
  • Мөнгө: дүнг сервер тооцно; хөнгөлөлт, хүргэлтийн өөрчлөлт бүр түүхэнд «хөнгөлөлт» шошготой, Супер админ шалгана.
  • Бодит өгөгдөл импортлоогүй. Тест өгөгдөл зөвхөн хөгжүүлэлтийн database-д (ALLOW_TEST_SEED=1).

12. Буцаах төлөвлөгөө

  • update.sh шинэчлэхийн өмнө автоматаар нөөц хуулбар авна. Асуудал гарвал өмнөх хувилбар (83015c7) руу буцааж, нөөцөөс сэргээнэ — шинэ хүснэгтүүд хуучин код ажиллахад саад болохгүй.

Үлдсэн эрсдэл ба анхаарах зүйл

  • Модуль 4–5-д хийгдэнэ: «Жолоочид оноосон», «Хүргэлтэд гарсан», «Хүргэсэн» төлөв рүү шилжүүлэх товч, жолоочийн «Маргааш» (#46). Төлөв, database, табууд бэлэн.
  • Meta CAPI бодит Facebook руу илгээгдсэнийг та Pixel ID, токен оруулсны дараа «Test event code»-оор Events Manager-т шалгах хэрэгтэй (би туршилтын хуурамч серверээр шалгасан).
  • «Пэйжийн түгээмэл бараа» — туршилт; хэрэггүй/төвөгтэй бол хэлээрэй, хасна.
  • Жилийн өдрөөрх пэйжийн тайлан ~0.8 сек (СА, маркетинг л ашиглана) — хүлээн зөвшөөрөгдөхүйц.

13. Дараагийн модульд шилжихэд

Танаас хэрэгтэй:

  1. Сервер дээр ./update.sh ажиллуулна. Дараа нь http://103.153.141.29 → Тохиргоо-д пэйжүүдээ нэмнэ, хүргэлтийн төлбөр шалгана; хүргэлт тусдаа бараанд «Үнэд хүргэлт багтсан» чагтыг авна.
  2. Захиалга-д хэдэн тест захиалга (УБ, орон нутаг, өнөөдөр, өөр өдөр) үүсгэж, засаж, цуцалж үзнэ. Дуудлагын бүртгэл, хар жагсаалт, тайланг үзнэ.
  3. Meta: Pixel ID, токен, Test event code оруулж нэг захиалга баталгаажуулаад Events Manager-т «Purchase» ирсэнийг шалгана (хүсвэл).
  4. Болсон бол «Модуль 3-ыг баталж байна» гэж бичнэ үү. Засах зүйл байвал хэлээрэй.

Модуль 4 (Падаан — жолоочид бараа өгөх) нь захиалгын төлөв, нөөц дээр суурилна. Таны баталгаа, тусгай зөвшөөрлөөс өмнө Модуль 4-ийг эхлүүлэхгүй.
