Падаан — жолоочид бараа өгөх

2026.11.11 · Хуучин ERP-ийн кодыг судалсан дүн, шинэ системд хэрхэн хийх санал, танаас асуух зүйлс. Код бичээгүй.

1. Хуучин ERP яаж ажилладаг байсан

  1. Хуваарилах (ахлах жолооч): «Ахлах жолооч» хуудсанд захиалгын мөр бүрт жолооч сонгох, эсвэл олныг чагтлаад нэг жолоочид өгнө. Захиалга «Бэлэн» болж, хүргэх огноо (өнөөдөр) тавигдана. «Он сар өдөртэй» захиалгыг хуваарилахгүй. Дүүргээр бүлэглэх, жолооч бүрийн ачаалал (20+ улаан) харагдана.
  2. Падаан үүсгэх (агуулах, iPad): жолооч + огноо сонгоод тэр жолоочийн бүх захиалгыг сонгож «Падаан үүсгэх». Нягтлангийн «OKEY» (тухайн жолоочийн өрийн зөвшөөрөл) байхгүй бол үүсгэхгүй.
  3. Бэлтгэх: падаанд бүх захиалгын бараа нэгтгэгдэж (2 пүүз + 1 пүүз = 3 пүүз) тавиурын дарааллаар жагсана. Агуулахынхан бараа бүрийг «Check» хийгээд «Бэлтгэсэн» → «Барааг бүрэн өгсөн».
  4. Хүлээн авах (жолооч): жолооч утсан дээрээ бараа бүрийг чагтлаад «Барааг бүрэн хүлээн авлаа» → захиалгууд «Хүргэлтэд гарсан» болно.
  5. Хэвлэх, түүх: падаанд огноо, жолооч, нийт захиалга, нийт дүн, захиалга бүрийн бараа (үйлчлүүлэгчийн утас, хаяггүй), агуулах ба жолоочийн баталгаа. Түүхэнд огноо, жолоочоор шүүнэ.
  6. Түгжээ: падаанд орсон захиалгыг засахгүй.

2. Хуучин ERP-ийн үлдэгдэл зөрдөг шалтгаан (энд илэрсэн)

  • Бараа жолоочид өгөхөд агуулахын үлдэгдэл хасагддаггүй байсан — жолоочийн гарт байгаа бараа агуулахад «байгаа» мэт тоологдож, зөвхөн «Хүргэсэн» дарахад хасагддаг байсан.
  • Жолооч цуцалсан барааг буцааж өгөхөд агуулахад нэмдэг — гэтэл өмнө нь хасагдаагүй тул давхар нэмэгддэг байсан (үлдэгдэл хөөрдөг гол шалтгаан).
  • Падаан үүссэний дараа хуваарилсан захиалга падаанд ордоггүй, алга болдог; нэг жолоочид хоёр падаан үүсэх боломжтой; падааныг «буцаах» товчинд эрхийн шалгалт байгаагүй.

3. Шинэ системд (санал)

Модуль 2-ын нэг журнал (StockMove) ашиглана — бараа хаана байна, тэнд л тоологдоно (дүрэм B2).

  • «Барааг бүрэн өгсөн» нь зэрэг дарахад нэг л удаа, тулгалт 0 зөрүү, тест 1 сая захиалга + 150 хэрэглэгч.
  • Хуучин шиг дэлгэц: «Ахлах жолооч» хуудас (хүснэгт, мөр бүрт жолооч сонгох, олноор хуваарилах, дүүргээр бүлэглэх, ачаалал), «Жолоочид бараа өгөх» (iPad, жолооч сонгох, бараа нэгтгэсэн Check хүснэгт), хэвлэх, түүх.
  • Жолооч өөрөө хүлээн авах (утас) нь Модуль 5-д; Модуль 4-т агуулах «өгсөн» дарахад шилжинэ.

4. Таны шийдвэр (#65)

  1. Нягтлангийн OKEY / ХОРИГ — заавал. «Жолоочид бараа өгөх» дэлгэцэд жолооч бүрийн хажууд OKEY/ХОРИГ; нягтлан, админ товчоор өгнө. OKEY-гүй жолоочид падаан үүсэхгүй.
  2. Падаан өгсний дараа хуваарилсан захиалга → маргаашийн падаанд автоматаар. Ахлах жолооч огноог өөрчилж болно. Захиалга алга болохгүй.
  3. Check заавал. Бүх барааг чагтлахгүй бол «Барааг бүрэн өгсөн» идэвхгүй.
  4. Жолоочийн хүлээн авах — Модуль 5-д. Модуль 4-т «Барааг бүрэн өгсөн» дармагц бараа агуулахаас жолоочид шилжиж, захиалга «Хүргэлтэд гарсан».

5. Ажлын дараалал

  1. Database: падаан (дугаартай, жолооч+огноогоор давхцахгүй), падааны мөр, нягтлангийн зөвшөөрөл; захиалгад жолооч, хүргэлтийн огноо.
  2. Бизнес логик: хуваарилах (нэг/олноор, дүүргээр), огноо солих, падаан үүсгэх/бэлтгэх/буцаах/өгөх, Check, журналын шилжилт агуулах → жолооч, засварын түгжээ, цуцлалт падаанд.
  3. Дэлгэц (хуучин шиг): «Ахлах жолооч», «Жолоочид бараа өгөх (iPad)», хэвлэх, түүх; захиалгын «Жолооч» багана, шүүлтүүр идэвхжинэ.
  4. Тест: зэрэг дарах, давхар падаан, сөрөг үлдэгдэл, тулгалт 0 зөрүү, 1 сая захиалга + 150 хэрэглэгч, Docker шинэчлэлт; тайлан.
