Жолооч — хүргэлт, цуцлалт, «Маргааш», буцаалт

2026.11.11 · Хуучин ERP-ийн кодыг судалсан дүн, таны хариулт, шинэ системд хэрхэн хийх. Таныг «Модуль 5-ын төлөвлөгөөг зөвшөөрч байна» гэж бичихээс өмнө код бичихгүй.

1. Хуучин ERP яаж ажилладаг байсан

  1. Жолоочийн апп: табууд «Бүгд · Хүргэлт · Хүргэсэн · Цуцласан · Маргааш · Өчигдөр», захиалгын карт (дугаар, утас — дарахад залгана, хаяг, санамж, бараа зурагтай, дүн), жолооч өөрөө дарааллын «#» дугаар бичнэ.
  2. «Хүргэсэн»: «Үйлчлүүлэгч мөнгөө өгсөн үү?» → «Төлсөн» (Бэлэн / Данс) эсвэл «Төлөөгүй» (өр үүснэ). Урьдчилж төлсөн бол тайлбар бичнэ.
  3. «Цуцлах»: шалтгаан (5+ тэмдэгт), «Мөнгө өгдөггүй хүн» чагтлавал хар жагсаалтад. Хүргэсэн захиалгыг «Цуцлах (буцаах)», цуцалсныг «Хүргэсэн болгох».
  4. «Маргааш»: захиалгыг ЦУЦАЛЖ, шинэ дугаартай хуулбар захиалга үүсгэдэг; «2 удаа» хязгаар ажилладаггүй; нэвтрэлт шалгадаггүй.
  5. «Опп-руу явуулах»: Бараа буруу / Дугаар буруу / Хаяг тодорхойгүй — ахлах оператор шийднэ (Опп-н алдаа / Жолоочийн алдаа / Зассан).
  6. Буцаалт (агуулах): огноо → жолооч → захиалгууд; «бүх барааг буцааж авах», хүргэсэн захиалгаас хэсэгчлэн буцаах, «өр үүсгэх» (дутуу бараа).
  7. Нэмэлт бараа: жолооч өөрөө бараа, тоо бичээд авч явна, зарсан мөнгөө тушаана, үлдсэнийг буцаана. Pickup: жолооч хуваарилаагүй захиалгыг өөрөө авна.

2. Хуучин үлдэгдэл яагаад зөрдөг байсан (энэ хэсэгт)

  • Падаанаар өгөхөд үлдэгдэл хасагддаггүй, «Хүргэсэн» үед л хасагддаг; харин цуцалсан/хойшилсон барааг буцааж авахад + нэмэгддэг → цуцлалт бүрт байхгүй бараа нэмэгддэг.
  • «Маргааш» нөөцийг 2 удаа суллаж, шинэ захиалгын нөөцийг «хулгайлдаг».
  • Буцааж авсан захиалгыг «Хүргэсэн болгох» дарахад дахин хасдаг; хэсэгчилсэн буцаалтыг давтан хийж болдог; нэмэлт барааны буцаалтыг 2 дарвал 2 дахин нэмдэг.
  • Үлдэгдэл, нөөц, боломжтой гэсэн 3 тоог тус тусад нь нэмж хасдаг — нэг удаа зөрвөл үүрд зөрнө.

V2-т эдгээр боломжгүй: бараа бүрийн хөдөлгөөн нэг журналаар (B2), байршил бүр (агуулах, жолооч) өөрийн үлдэгдэлтэй, давхар дарахад нэг л удаа бүртгэгдэнэ, цаг тутам автомат тулгалт.

4. Хийх ажлууд

  1. Жолоочийн апп (/driver, утсанд зориулсан): хуучин табууд — Бүгд · Хүргэлт · Хүргэсэн · Цуцласан · Маргааш · Өчигдөр, мөн «Авах» (Pickup), «Нэмэлт бараа», «Миний бараа» (гарт байгаа, буцаах). Карт хуучин шиг; утас дарахад залгана; «#» дараалал. Захиалгыг хүргэх өдөр + жолоочоор сонгоно (хуучны «үүссэн өдөр» алдаа гарахгүй). Урт хаяг, санамж багтана (B3).
  2. Хүргэсэн: бараа бүр чагттай (анхдагч бүгд); болиулсныг чагтаа авна → дүн шууд шинэчлэгдэнэ; дараа нь Бэлэн / Данс / Төлөөгүй (өр), урьдчилж төлсөн бол тайлбар. Мөнгөний дүн хадгалагдана — тооцоо, цалин Модуль 6-д (хэсэгчилсэн хүргэлтийн тооцоог тэнд заавал шалгана).
  3. Цуцлах, Маргааш, Опп-руу явуулах, Цуцлах (буцаах), Хүргэсэн болгох — дээрх хүснэгтээр. «Маргааш» 2 удаа, дараа нь цоож.
  4. Асуудал (Опп-руу): захиалга хүргэлтэд хэвээр, «Асуудалтай» тэмдэг; ахлах оператор «Зассан» (жолооч үргэлжлүүлнэ) эсвэл «Цуцлах» (Опп-н / Жолоочийн / Маркетингийн / Агуулахын алдаа гэж тэмдэглэнэ — торгууль Модуль 7).
  5. Буцаалт хүлээн авах (агуулах): жолооч сонгоход түүний гарт байгаа, хүргэлтэд хамааралгүй бүх бараа (цуцалсан, хойшилсон, болиулсан, нэмэлт) нэг жагсаалтаар; бараа бүрийн ирсэн тоог оруулж «Хүлээн авсан». Давхар дарахад нэг удаа. Дутууг жолоочийн «буцаагаагүй» үлдэгдэлд үлдээнэ.
  6. Нэмэлт бараа (хуучин шиг): жолооч бараа, тоог сонгож авна → бараа агуулахаас жолоочид шилжинэ (журналаар). Зарсныг жолооч бүртгэнэ — үнэ системийн үнээр (хуучин шиг жолооч өөрөө үнэ бичихгүй); үлдсэнийг буцаалтаар.
  7. Pickup (хуучин шиг): жолооч хуваарилаагүй «Шинэ» захиалгыг өөрөө авна — Модуль 4-ийн дүрэм хэвээр (падаан өгөгдсөн бол маргааш, падаанд автоматаар нэмэгдэнэ, төлбөр хүлээж буй / он сар өдөртэйг авахгүй). Ахлах жолоочид харагдана.
  8. Жолоочийн хяналт (Супер админ, Админ, Ахлах жолооч, Нягтлан): өдрөөр, жолооч бүрээр — оноосон, хүргэлтэд, хүргэсэн, цуцалсан, хойшилсон, гарт байгаа бараа (ширхэг), 1+ өдөр буцаагаагүй бараа, авсан мөнгө (Бэлэн / Данс / Өр) — зөвхөн харах.
  9. Аюулгүй байдал: бүх товч сессээр — жолооч зөвхөн өөрийн захиалгад (хуучинд хэн ч дарж болдог байсан).
  10. Өөрчлөгдөхгүй: Meta CAPI хүргэлт/цуцлалтад илгээхгүй (хуучин шиг).

5. Таны шийдвэр (#73)

  1. «Маргааш»: бараа заавал агуулахад буцаж, маргааш шинэ падаанаар; захиалгыг бараа буцахаас өмнө дурын жолоочид оноож / жолооч өөрөө авч болно.
  2. «Маргааш» 2 удаа, дараа нь цоож.
  3. Хэсэгчилсэн хүргэлт: жолооч «Хүргэсэн» дарахаасаа өмнө болиулах барааг чагтаа авна, жолоочид төвөггүй; тооцоолол зөрөхгүй — Модуль 6-д заавал шалгана.
  4. Нэмэлт бараа, Pickup — хуучин шиг.

6. Ажлын дараалал

  1. Өгөгдлийн сан: хүргэлтийн мэдээлэл (төлбөрийн хэлбэр, дүн, болиулсан мөр, хойшилсон тоо, асуудал), нэмэлт бараа, буцаалтын баримт; журналын шинэ төрлүүд: Хүргэсэн, Буцаан авсан (үйлчлүүлэгчээс), Жолоочоос буцаалт, Нэмэлт бараа, Нэмэлт бараа зарсан.
  2. Сервисүүд + эрх + түүх (writeAudit).
  3. Жолоочийн апп, буцаалт хүлээн авах (агуулах), асуудал шийдэх (ахлах оператор), жолоочийн хяналт, ахлах жолоочийн KPI-д «хойшилсон».
  4. Тест: бүх замын үлдэгдэл (тулгалт 0), давхар дарах, зэрэг үйлдэл, урт текст (B3), 150 хэрэглэгчийн ачаалал (жолооч 40+ зэрэг хүргэж байхад), Docker шинэчлэл.
  5. Тайлан, дэлгэцийн зураг → таны баталгаа.
Танаас: зөвшөөрвөл «Модуль 5-ын төлөвлөгөөг зөвшөөрч байна» гэж бичнэ үү. Өөрчлөх зүйл байвал хэлээрэй.
